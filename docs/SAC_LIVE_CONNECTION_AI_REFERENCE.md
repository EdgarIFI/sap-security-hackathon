## SECTION 1 — WHAT WAS BUILT AND WHY

### Objective
Connect SAP Analytics Cloud (SAC) to SAP HANA Cloud using **Live Connection** (real-time, not Import) so that a security dashboard updates automatically as the ingestion pipeline inserts data into HANA.

### Architecture

```
DBADMIN.<TABLE_NAME> (source table in HANA)
        │
        │  .hdbsynonym (bridge from HDI Container to external schema)
        ▼
HDI Container (isolated namespace in HANA, created via CF service)
        │
        │  .hdbcalculationview (type CUBE, with ≥1 Measure)
        ▼
SAP Analytics Cloud
        │
        │  Live Connection (SAC queries HANA in real time)
        ▼
Dashboard (auto-refreshes on data changes)
```

### Why each component is required
- **Synonym**: HDI Containers cannot see tables outside their own schema. A synonym creates a named reference to an external table (e.g., `DBADMIN.RAW_LOGS_LLM`).
- **HDI Container**: Isolated namespace with its own roles, users, and lifecycle. Required by SAC Live Connection — SAC cannot connect directly to raw HANA tables.
- **Calculation View (CUBE)**: The ONLY object type that SAC Live Connection can consume as a data source. Must have at least one column marked as Measure.
- **Measure**: A numeric column with an aggregation function (SUM, AVG, COUNT, etc.). SAC requires at least one Measure to build any chart. Without a Measure, the CV deploy fails with error [170109].

## SECTION 3 — USER MODEL AND PERMISSION CHRONOLOGY

### Users involved

| User | Type | Created By | Purpose | Critical Constraints |
|---|---|---|---|---|
| `DBADMIN` | Admin | HANA setup | All admin operations, GRANTs | Cannot DROP schemas owned by HDI users in Trial (insufficient privilege) |
| `SAC_USER` | Human | DBADMIN via SQL | SAC Live Connection login | Must have HDI access_role + external_privileges_role |
| `PIPELINE_USER` | Technical | DBADMIN via SQL | Pipeline writes to HANA | NEVER use for SAC — no interactive login |
| `<CONTAINER>#OO` | Technical | HDI broker | Owns deployed objects in container | Needs SELECT WITH GRANT OPTION on external tables |
| `<CONTAINER>#DI` | Technical | HDI broker | Deployment operations | Auto-managed, no manual intervention needed |

### Permission grant order (CRITICAL — order matters)

```
STEP 1: Create HDI Container (Phase 1 deploy or wizard)
         ↳ This creates #OO and #DI users automatically
         ↳ #OO exists but has NO permissions on external tables yet

STEP 2: GRANT SELECT to #OO (AFTER container exists, BEFORE CV deploy)
         GRANT SELECT ON DBADMIN.<TABLE> TO "<CONTAINER>#OO" WITH GRANT OPTION;
         ↳ WITH GRANT OPTION is mandatory — #OO must propagate access to container roles
         ↳ Without this, CV deploy fails with "not authorized to access synonym target"

STEP 3: Deploy Calculation View (AFTER #OO has SELECT)
         ↳ HDI engine verifies that #OO can access all data sources referenced by the CV
         ↳ If #OO lacks permissions, deploy fails even if DBADMIN can read the table

STEP 4: Create SAC_USER (anytime before SAC connection)
         CREATE USER SAC_USER PASSWORD <pwd> NO FORCE_FIRST_PASSWORD_CHANGE;
         GRANT SELECT ON SCHEMA DBADMIN TO SAC_USER;

STEP 5: Grant HDI roles to SAC_USER (AFTER successful CV deploy)
         GRANT "<CONTAINER>::access_role" TO SAC_USER;
         GRANT "<CONTAINER>::external_privileges_role" TO SAC_USER;
         ↳ These roles are auto-generated by HDI when the container is created
         ↳ Role names follow pattern: <SCHEMA_NAME>::access_role
         ↳ Find exact names: SELECT ROLE_NAME FROM ROLES WHERE ROLE_NAME LIKE '%<CONTAINER>%';

STEP 6: Test SAC_USER access (BEFORE configuring SAC)
         Connect to HANA as SAC_USER and run:
         SELECT TOP 10 * FROM "<CONTAINER>"."<CV_NAME>";
         ↳ Must return data. If not, roles were not granted correctly.
```

### Phase 0 — Verify CF is clean

```bash
cf services
cf apps
```

No orphaned HDI services or apps should exist. If they do:
```bash
cf delete-service <service-name> -f
# If binding is stuck:
cf purge-service-instance <service-name> -f
```

Verify in HANA (as DBADMIN):
```sql
-- Check for orphaned schemas
SELECT SCHEMA_NAME, SCHEMA_OWNER FROM SCHEMAS
WHERE SCHEMA_NAME NOT LIKE 'SYS%' AND SCHEMA_NAME NOT LIKE '_SYS%'
  AND SCHEMA_NAME NOT LIKE 'HANA_%' AND SCHEMA_NAME NOT LIKE 'SAP_%'
  AND SCHEMA_NAME NOT IN ('PUBLIC', 'DBADMIN', 'PAL_STEM_TFIDF', 'UIS')
ORDER BY CREATE_TIME DESC;

-- Check for orphaned technical users
SELECT USER_NAME, CREATE_TIME FROM SYS.USERS
WHERE USER_NAME NOT LIKE 'SYS%' AND USER_NAME NOT LIKE '_SYS%'
  AND USER_NAME NOT IN ('DBADMIN', 'SAC_USER', 'PIPELINE_USER', 'PUBLIC')
ORDER BY CREATE_TIME DESC;
```

If orphaned schemas exist from previous attempts: leave them (DBADMIN in Trial cannot DROP HDI-owned schemas). Use a DIFFERENT project name to avoid collisions.

**Security action:** Revoke any GRANTs that orphaned #OO users have on production tables:
```sql
REVOKE SELECT ON DBADMIN.<TABLE> FROM "<ORPHANED_OO_USER>";
```

1. BAS → File → New Project from Template → SAP HANA Database Project
2. Configuration:

| Field | Value | Notes |
|---|---|---|
| Project name | `<project_name>` | No spaces, no hyphens in some versions. Avoid names of orphaned containers |
| Module name | `db` | Standard convention, don't change |
| Database version | HANA Cloud | |
| Schema name | (leave empty) | HDI generates its own |
| Namespace | (leave empty) | |
| Bind to CF | Yes | |
| Service instance name | `<project_name>_hdi_db` | Use underscores, not spaces. This name appears in `cf services` |

3. **CRITICAL FIX**: BAS wizard sometimes generates `mta.yaml` with a generic resource name (`hdi_db`). Verify and fix:

```bash
cat mta.yaml
```

The resource name in `modules.requires.name` and `resources.name` MUST match the service instance name. Correct `mta.yaml` structure:

```yaml
_schema-version: "2.1"
ID: <project_name>
version: 0.0.1
modules:
- name: db
  type: hdb
  path: db
  requires:
  - name: <project_name>_hdi_db
    properties:
      TARGET_CONTAINER: ~{hdi-container-name}
resources:
- name: <project_name>_hdi_db
  type: com.sap.xs.hdi-container
  parameters:
    service: hana
    service-plan: hdi-shared
  properties:
    hdi-container-name: ${service-name}
```

**WARNING**: Some editors (including Claude.ai chat) auto-convert `com.sap.xs.hdi-container` into a hyperlink `[com.sap](http://com.sap).xs.hdi-container`. This breaks the YAML. Always verify the raw file content.

4. Verify service instance was created:
```bash
cf services
# Must show: <project_name>_hdi_db   hana   hdi-shared   create succeeded
```

5. Identify the HDI Container schema and Object Owner:
```sql
SELECT SCHEMA_NAME, SCHEMA_OWNER FROM SCHEMAS
WHERE SCHEMA_NAME LIKE '<PREFIX>%' OR SCHEMA_OWNER LIKE '<PREFIX>%'
ORDER BY SCHEMA_NAME;

SELECT USER_NAME, CREATE_TIME FROM SYS.USERS
WHERE USER_NAME LIKE '<PREFIX>%' ORDER BY USER_NAME;
```

Record these values — they are needed for GRANTs later:
- Container schema name (e.g., `SOC_DASHBOARD_HDI_DB_1`)
- Object Owner name (e.g., `SOC_DASHBOARD_HDI_DB_1#OO`)

### Phase 5 — Create Calculation View (XML method)

**CRITICAL CONTEXT**: The BAS visual Calculation View editor has a known bug (`"Unable to find service undefined"`) that prevents it from finding Data Sources even when the binding is correctly configured. The workaround is to write the XML directly. This is functionally identical — the visual editor generates the same XML format internally.

**Step 5.1 — Get exact column names from HANA:**

```sql
SELECT COLUMN_NAME, DATA_TYPE_NAME
FROM TABLE_COLUMNS
WHERE SCHEMA_NAME = 'DBADMIN'
  AND TABLE_NAME = '<TABLE_NAME>'
ORDER BY POSITION;
```

**CRITICAL**: Use the exact column names returned by this query. HANA column names are UPPERCASE. Do NOT use column names from API documentation — they may differ (e.g., `LLM_RESPONSE_TIME` vs `llm_response_time_ms`, `EVENT_TIMESTAMP` vs `@timestamp`).

**Step 5.2 — Identify Measures and Attributes:**

- **Measures**: Numeric columns (INTEGER, DOUBLE, DECIMAL) that will be aggregated (SUM, AVG, COUNT). At least ONE is required for CUBE type.
- **Attributes**: All other columns (NVARCHAR, TIMESTAMP) used for filtering and grouping.

**Step 5.3 — Create the XML file:**

**File:** `db/src/<CV_NAME>.hdbcalculationview`

**TEMPLATE — Copy and modify (replace ALL placeholders):**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Calculation:scenario xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xmlns:Calculation="http://www.sap.com/ndb/BiModelCalculation.ecore"
  id="<CV_NAME>"
  applyPrivilegeType="NONE"
  dataCategory="CUBE"
  schemaVersion="3.0"
  outputViewType="Aggregation"
  enforceSqlExecution="false">
  <descriptions defaultDescription="<CV_NAME>"/>
  <localVariables/>
  <variableMappings/>
  <dataSources>
    <DataSource id="<TABLE_NAME>" type="DATA_BASE_TABLE">
      <resourceUri><TABLE_NAME></resourceUri>
    </DataSource>
  </dataSources>
  <calculationViews>
    <calculationView xsi:type="Calculation:AggregationView" id="Aggregation_1">
      <viewAttributes>
        <!-- List ALL columns you want to expose (measures + attributes) -->
        <viewAttribute id="<COLUMN_1>"/>
        <viewAttribute id="<COLUMN_2>"/>
        <!-- ... add more as needed ... -->
      </viewAttributes>
      <input node="<TABLE_NAME>">
        <!-- Map each column: target = viewAttribute id, source = actual column name in table -->
        <mapping xsi:type="Calculation:AttributeMapping" target="<COLUMN_1>" source="<COLUMN_1>"/>
        <mapping xsi:type="Calculation:AttributeMapping" target="<COLUMN_2>" source="<COLUMN_2>"/>
        <!-- ... add more as needed ... -->
      </input>
    </calculationView>
  </calculationViews>
  <logicalModel id="Aggregation_1">
    <attributes>
      <!-- List NON-NUMERIC columns (NVARCHAR, TIMESTAMP) as attributes -->
      <attribute id="<ATTR_COLUMN>" order="1" displayAttribute="false" attributeHierarchyActive="false">
        <keyMapping columnObjectName="Aggregation_1" columnName="<ATTR_COLUMN>"/>
      </attribute>
      <!-- ... add more attributes, incrementing order ... -->
    </attributes>
    <calculatedAttributes/>
    <baseMeasures>
      <!-- List NUMERIC columns (INTEGER, DOUBLE) as measures -->
      <!-- aggregationType: "sum" for counts/totals, "avg" for averages, "min"/"max" as needed -->
      <measure id="<MEASURE_COLUMN>" order="N" aggregationType="sum" measureType="simple">
        <measureMapping columnObjectName="Aggregation_1" columnName="<MEASURE_COLUMN>"/>
      </measure>
      <!-- AT LEAST ONE MEASURE IS REQUIRED — deploy fails without it -->
    </baseMeasures>
    <withParameters/>
  </logicalModel>
</Calculation:scenario>
```

### CRITICAL XML RULES (violations cause deploy failure):

| Rule | Correct | Wrong | Error if violated |
|---|---|---|---|
| `xmlns:xsi` declaration | On the root `<Calculation:scenario>` tag | On the `<calculationView>` tag only | Various XML parse errors |
| `<input node="...">` value | Exact DataSource `id` value (e.g., `RAW_LOGS_LLM`) | With `#` prefix (e.g., `#RAW_LOGS_LLM`) | [34011] Input name not set |
| `<input>` wrapper | Direct child of `<calculationView>`, NO `<inputNodes>` wrapper | Wrapped in `<inputNodes>` | [34011] Input name not set |
| Column names | UPPERCASE as they appear in HANA | lowercase or API-style names | Column not found |
| At least one `<measure>` | Present in `<baseMeasures>` | Missing or empty `<baseMeasures>` | [170109] No measures defined in cube |
| `<viewAttribute>` in Aggregation | NO `aggregationType` attribute | With `aggregationType="sum"` | May cause unexpected behavior |
| `aggregationType` | Only on `<measure>` elements in `<baseMeasures>` | On `<viewAttribute>` | May cause unexpected behavior |

### Phase 6 — Deploy Calculation View

**CRITICAL**: Always clean build artifacts and bump version before deploying a CV change.

```bash
cd ~/projects/<project_name>

# 1. Bump version (prevents CF from using cached archive)
# Edit mta.yaml: version: 0.0.1 → 0.0.2 (or next number)
sed -i 's/version: <old>/version: <new>/' mta.yaml

# 2. Clean previous build artifacts
rm -rf mta_archives/
rm -rf .<project_name>_mta_build_tmp/

# 3. Build
mbt build
# Expected output ends with: INFO cleaning temporary files...

# 4. Deploy
cf deploy mta_archives/<project_name>_<version>.mtar
# If asked about ongoing operation: respond 'y'
# Expected output: Process finished.
# Typical duration: 2-4 minutes
```

**Post-deploy verification:**

```sql
-- Verify CV exists
SELECT VIEW_NAME, VIEW_TYPE FROM VIEWS
WHERE SCHEMA_NAME = '<CONTAINER_SCHEMA>'
  AND VIEW_NAME = '<CV_NAME>';
-- Expected: one row with VIEW_TYPE = 'CALC'

-- Verify CV returns data (connect as user with access_role, not DBADMIN)

```

## SECTION 5 — COMPLETE ERROR CATALOG

### Error: "Unable to find service undefined" (BAS Visual Editor)
```
Context: BAS Calculation View visual editor → Add Data Source → search
Symptom: No data sources found, error message displayed
Root cause: BAS editor bug — cannot parse .env binding format
Impact: Cannot use visual editor to create/edit Calculation Views
Resolution: Write CV XML directly (see Phase 5 template)
Prevention: Always have XML template ready. Do not depend on visual editor.
```

### Error: "The container's object owner is not authorized" [8250505]
```
Context: cf deploy of synonym or CV
Symptom: Deploy fails during HDI make
Root cause: #OO lacks SELECT on external table
Resolution: GRANT SELECT ON DBADMIN.<TABLE> TO "<CONTAINER>#OO" WITH GRANT OPTION;
Prevention: Always grant #OO permissions AFTER first deploy creates the user, BEFORE deploying CV
Verification: SELECT GRANTEE, PRIVILEGE, IS_GRANTABLE FROM SYS.GRANTED_PRIVILEGES WHERE GRANTEE = '<OO>';
```

### Error: "No measures defined in a cube" [170109]
```
Context: cf deploy of .hdbcalculationview
Symptom: Deploy fails during HDI make
Root cause: Calculation View type CUBE has no column marked as Measure in <baseMeasures>
Resolution: Add at least one <measure> element to <baseMeasures> in the XML
Prevention: Always include numeric columns as measures. Verify XML has <baseMeasures> with content.
```

### Error: "Inconsistent calculation model — Input name not set" [34011]
```
Context: cf deploy of .hdbcalculationview
Symptom: Deploy fails with column store error 2048
Root cause: <input> element has incorrect node reference
Resolution: Use <input node="TABLE_NAME"> where TABLE_NAME exactly matches <DataSource id="TABLE_NAME">
            Do NOT use # prefix. Do NOT wrap in <inputNodes>.
Prevention: Follow the exact XML template in this document.
Verification: grep "input node" db/src/<CV_NAME>.hdbcalculationview
```

### Error: "Column not found" or silent deploy failure
```
Context: cf deploy of .hdbcalculationview
Symptom: Deploy fails or CV returns no data
Root cause: Column names in XML don't match actual HANA column names
Resolution: Query TABLE_COLUMNS for exact names and update XML
Prevention: ALWAYS run this query before writing XML:
    SELECT COLUMN_NAME, DATA_TYPE_NAME FROM TABLE_COLUMNS
    WHERE SCHEMA_NAME = 'DBADMIN' AND TABLE_NAME = '<TABLE>'
    ORDER BY POSITION;
```

### Error: Deploy uses cached/old version
```
Context: cf deploy after fixing XML
Symptom: Same error repeats despite file changes
Root cause: CF reuses .mtar archive with same version number
Resolution: 1. Bump version in mta.yaml
            2. rm -rf mta_archives/ .<project>_mta_build_tmp/
            3. mbt build
            4. cf deploy with new .mtar filename
Prevention: ALWAYS increment version and clean artifacts before retry
```

### Error: "An operation for a service binding is in progress"
```
Context: cf delete-service or cf unbind-service
Symptom: Cannot delete or unbind HDI service
Root cause: Previous binding/unbinding operation stuck in CF
Resolution: Wait 2-5 minutes, then retry. If still stuck: cf purge-service-instance <name> -f
Prevention: Don't interrupt deploy/undeploy operations. Let them complete or fail naturally.
```

### Error: "insufficient privilege" when DBADMIN tries to DROP HDI schemas
```
Context: Cleanup of orphaned HDI containers
Symptom: DBADMIN cannot DROP SCHEMA or DROP USER of HDI-created objects
Root cause: HANA Cloud Trial DBADMIN is not a superuser — cannot drop objects owned by HDI users
Resolution: Leave orphans in place, use different project names. Revoke GRANTs on production tables.
            Alternative: GRANT DATA ADMIN TO DBADMIN (may or may not work in Trial)
Prevention: Use cf undeploy for clean teardowns before creating new projects
```

### Error: mta.yaml type field becomes hyperlink
```
Context: Editing mta.yaml in certain editors or chat interfaces
Symptom: com.sap.xs.hdi-container becomes [com.sap](http://com.sap).xs.hdi-container
Root cause: Editor auto-links "com.sap" as a URL
Resolution: Manually fix to: type: com.sap.xs.hdi-container (no brackets or parentheses)
Prevention: Always verify mta.yaml with cat after editing. Use terminal-based editors for YAML.
```

## SECTION 6 — REPLICATION PROCEDURE FOR NEW TABLES

To add a new table to the same HDI Container (e.g., `RAW_LOGS_SISTEMA` or `ALERTS`):

### Step 1 — Get table metadata
```sql
SELECT COLUMN_NAME, DATA_TYPE_NAME
FROM TABLE_COLUMNS
WHERE SCHEMA_NAME = 'DBADMIN' AND TABLE_NAME = '<NEW_TABLE>'
ORDER BY POSITION;
```

### Step 2 — Identify measures
Pick at least one INTEGER or DOUBLE column for aggregation.

### Step 3 — Grant #OO access to the new table
```sql
GRANT SELECT ON DBADMIN.<NEW_TABLE> TO "<CONTAINER_SCHEMA>#OO" WITH GRANT OPTION;
```

### Step 4 — Create synonym
Create `db/src/<NEW_TABLE>.hdbsynonym`:
```json
{
  "<NEW_TABLE>": {
    "target": {
      "object": "<NEW_TABLE>",
      "schema": "DBADMIN"
    }
  }
}
```

### Step 5 — Create Calculation View
Create `db/src/CV_<NEW_TABLE>.hdbcalculationview` using the XML template from Section 4, Phase 5. Replace all placeholders with actual column names (UPPERCASE).

### Step 6 — Deploy
```bash
cd ~/projects/<project_name>
# Bump version
sed -i 's/version: <current>/version: <next>/' mta.yaml
rm -rf mta_archives/ .<project_name>_mta_build_tmp/
mbt build
cf deploy mta_archives/<project_name>_<version>.mtar
```

### Step 7 — Verify
```sql
SELECT VIEW_NAME FROM VIEWS
WHERE SCHEMA_NAME = '<CONTAINER_SCHEMA>' AND VIEW_NAME = 'CV_<NEW_TABLE>';
```

### Step 8 — SAC_USER already has access_role
If SAC_USER was already granted `access_role` and `external_privileges_role` in a previous phase, they automatically have access to new objects deployed to the same container. No additional GRANTs needed.

### Step 9 — Add to SAC
In SAC, the new CV appears automatically in the same connection. Create a new model pointing to `CV_<NEW_TABLE>`.

## SECTION 7 — SECURITY RULES FOR AI ASSISTANTS

When helping a human with this procedure, the AI assistant must:

1. **NEVER ask the user to share**: passwords, Bearer tokens, JWT tokens, API keys, connection strings with passwords, HANA hostnames, webhook URLs with tokens, personal emails, or `default-env.json` / `.env` file contents.

2. **ALWAYS remind** the user to verify `.gitignore` excludes `.env*`, `default-env.json`, and `node_modules/` before any git operation.

3. **ALWAYS use sanitization** when requesting diagnostic output:
   - `sed 's/password[^,]*/password=REDACTED/gi'` for logs
   - `grep -c` (count only) instead of `cat` for credential files
   - `Object.keys()` instead of `JSON.stringify()` for credential objects

4. **Flag immediately** if the user pastes content containing:
   - Strings starting with `eyJ` (JWT tokens)
   - Strings after `password=` or `pwd=`
   - Full HANA hostnames (`*.hana.ondemand.com`)
   - `VCAP_SERVICES` JSON with values (not just keys)

5. **Safe to share**: error codes `[170109]`, `[34011]`, `[8250505]`; schema names; table names; column names; CF process IDs; plugin names `com.sap.hana.di.*`; user names `#OO`, `#DI`; role names.
